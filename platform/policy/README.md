# Scoped policy evaluator

This package evaluates one concrete flow against one explicitly scoped, ordered policy bundle. Its pure API is `policy.Evaluate(Bundle, Flow) (Result, error)`. Snapshot ID, device ID and context are mandatory; use an explicit context such as `default` when no virtual context applies. Duplicate rule IDs/positions, invalid tuple values and scope mismatch are validation errors. Inputs to this package are normalized policy data. The separate [ASA investigation adapter](../../docs/FIREWALL_INVESTIGATION.md) produces bundles from running configurations.

The supported subset is IPv4/IPv6 literal and CIDR matching, `any` (either family), `any4` and `any6`, numeric IP protocols (plus TCP/UDP/ICMP/ICMPv6 aliases), numeric source/destination ports and inclusive ranges, enabled state, first-match order, and explicit defaults on complete bundles. Rules may use protocol `any` or `ip` as a wildcard, without port predicates; query flows must specify a concrete protocol. Named or otherwise unparsed predicates remain unresolved. They yield indeterminate when the rule could still match; a known mismatch in another supported predicate safely removes the candidate. An unresolved earlier candidate blocks a later rule verdict. Disabled rules are omitted from consideration.

Flows and address predicates use native, unscoped IPv4 or IPv6. IPv4-mapped IPv6 and zone-qualified IPv6 are rejected to avoid ambiguous namespace/family matching. Rule `unsupported` labels may be `application`, `user`, `schedule`, `nat`, `route`, `return_path`, `stateful`, `zone_inheritance`, `negation`, `object_expansion`, `vendor_default` or `device_state`; the result reports labels only, never copies unresolved predicate values.

Verdicts are `permit`, `deny`, or `indeterminate`. An incomplete bundle cannot produce a definitive result, including from an apparent rule match, because omitted earlier rules could change the decision. Results carry engine contract version `graphlayer-policy-v3`, the input scope and tuple, candidate or decisive rule, considered enabled rules, evidence references, supported semantics, encountered unsupported dimensions and an explicit policy-only assumption. They also include `rule_traces` in evaluation order for every enabled rule considered, with an overall `matched`, `not_matched` or `unresolved` outcome and a state for each source, destination, protocol and port predicate. Known mismatches remain visible alongside unresolved predicates when they eliminate a candidate. Traces use bounded static reason text and never repeat unresolved predicate values. Evidence references are identifiers supplied by the caller; this evaluator does not verify their provenance. Fixture evidence IDs are synthetic demonstration labels, not hashes or provenance claims.

NAT, route selection, return traffic, stateful behavior, application/user identity, schedules, zone inheritance, negation, object expansion, vendor defaults and device state are unsupported. A permit means only that the modeled policy predicates permit the flow; it is not a reachability claim. Policy input size is bounded by the CLI and rule count by the package. There is no network or device access.

From the `platform` directory, replay the sample with:

```powershell
go run ./cmd/graphlayer-policy --bundle ./policy/fixtures/allow-https.bundle.json --flow ./policy/fixtures/allow-https.flow.json
```

The CLI accepts strict JSON only, rejects unknown fields and trailing JSON, limits each input to 8 MiB, emits JSON to stdout, and exits nonzero for malformed input. Bundle JSON must explicitly provide `complete`, a `rules` array (which may be empty), and each rule's `enabled` and `position` fields; explicit `false` and position `0` are valid. JSON parser errors omit input contents; domain validation errors may identify the offending rule ID. Predicate strings are not copied into validation errors.
